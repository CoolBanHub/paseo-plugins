# 飞书机器人（lark-bot）

把飞书机器人接入 Paseo：在设置里为每个飞书会话（群聊或单聊）指定一个 provider，在群里 @ 机器人（或单聊直接发消息）即由该 provider 的智能体处理，结果以**话题回复**的形式回到被 @ 的那条消息下。

## 工作方式

```
飞书（WebSocket 事件订阅，经 lark-cli）
  └→ lark-cli event consume im.message.receive_v1（插件管理的长驻子进程，NDJSON 流）
       └→ 按 message_id 去重，并按会话串行预处理
            └→ 路由：chat_id → 绑定的 provider / cwd / systemPrompt / 回复格式
                 └→ 群聊：每个话题一个智能体会话；单聊：整个 chat 一个持续会话
                      └→ agent.turn_ended 统一回复：lark-cli im +messages-reply 挂回原消息话题
权限请求 → 默认只在 Paseo 处理；开启通知后发到话题
```

- 事件订阅走 lark-cli 的长连接模式，插件只需本机能跑 lark-cli 并访问 `open.feishu.cn`，无需公网地址。
- 绑定里可写裸 provider id（如 `dsh`），创建会话时自动补全为 `provider/默认模型`（新版 Paseo 要求 `provider/model` 格式）。
- 回复统一由 `agent.turn_ended` 驱动：权限批准后的继续执行、超过 10 分钟仍在跑的轮次，完成后都会回到原话题。`run()` 返回 idle 只作为兜底，不会单独释放队列。
- 群聊需要 @ 机器人；单聊（p2p）直接发消息即触发。群聊里未 @ 的消息只在**已绑定**的会话中记录为上下文；未绑定会话不采集文本、图片或视频。
- 其他机器人 @ 本机器人也会响应（支持群内 agent 协作）；插件自身发出的消息不会再触发自己。两个机器人都开启富文本接力时仍可能互相触发，建议只在一侧开启。

## 前置条件

- Paseo ≥ 0.11.4；
- 已安装 lark-cli；应用凭证二选一：在插件界面直接填写 App ID / App Secret（保存时自动验证并写入 lark-cli），或沿用 `lark-cli config init` 已配置的凭证；
- 飞书开发者后台（该 appId）：
  - 事件订阅切换为**长连接**方式，并添加事件 `im.message.receive_v1`（接收消息）；
  - 基础权限：
    - `im:message:send_as_bot`：以机器人身份回复；
    - `im:message.p2p_msg:readonly`：接收单聊消息（需要单聊时）；
    - `im:message.group_at_msg:readonly`：接收群里 @ 机器人的消息；
    - `im:message.group_at_msg.include_bot:readonly`：接收群里其他机器人 @ 本机器人的消息；
    - `application:bot.basic_info:read`：读取机器人信息。
  - 上下文/媒体/群列表所需权限：
    - `im:message:readonly`：读取消息详情（话题根消息、mget）；
    - `im:message.group_msg`（敏感权限）：读取群消息详情、下载群内图片/视频；没有它时，话题根消息和媒体会失败并降级为无上下文；
    - 如果要接收**未 @ 的群消息**（完整群历史），还需要 `im:message.group_msg` 或 `im:message.group_msg:readonly`；这是敏感权限，请按实际隐私边界决定是否开启；
    - `im:chat:read`：设置界面的群列表选择器。
- 机器人已被拉进目标群（单聊则需用户能搜到该机器人）。

## 设置

host 级设置（`lark_bot`，version 1），在 Paseo 侧边栏的「飞书机器人」独立界面配置（命令面板搜「打开飞书机器人」也可进入）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `appId` / `appSecret` | `""` | 飞书应用凭证。两者都填写并保存后，插件先向飞书验证有效性（无效则拒绝写入、沿用现有配置），再非交互写入 lark-cli 并重启事件总线。留空沿用 lark-cli 已有配置。按当前本地使用场景，**在 Paseo 设置中明文保存、不加密**；同一 App ID 更换 Secret 也会重新验证并写入 |
| `larkCliPath` | `""` | lark-cli 绝对路径；空表示自动发现（PATH → nvm → Homebrew → /usr/local） |
| `replyInThread` | `true` | 回复进被 @ 消息的话题；关闭则回复到消息流 |
| `sessionIdleMinutes` | `30` | 话题空闲多少分钟后该话题新建智能体会话（0 表示一直复用） |
| `maxReplyChars` | `4000` | 回复超过该长度截断并提示打开 Paseo 查看 |
| `notifyUnmatched` | `false` | 未绑定的会话 @ 机器人时是否回复配置提示 |
| `ackOnReceive` | `true` | 收到 @ 消息立即回复一条「收到，正在处理」确认 |
| `notifyPermission` | `false` | 权限请求是否通知到群。默认关闭：直接在 Paseo 客户端处理，完成后结果仍回到话题 |
| `chats[]` | `[]` | 会话绑定列表，每项含 `chatId`、`chatName`、`provider`（可带 `/model`）、`cwd`、`systemPrompt`、`replyFormat` |

- 绑定列表为空时事件监听不启动；保存设置即生效（监听进程随绑定列表启停）。设置保存会串行执行，避免并发 stop/start。
- 回复格式：`markdown`（默认，排版最佳）/ `text`（原样纯文本）/ `post`（富文本，保留 `<at user_id=…>` 以 @ 群里其他机器人，实现 agent 接力）。
- `cwd` 留空表示用户主目录；支持 `~/` 开头的路径。生产使用时建议填一个专用、低权限的项目目录。
- 设置界面的会话选择器来自 lark-cli 的群列表；单聊的 chat_id 拿不到，可先给机器人发条消息，再从「添加会话」的“最近发过消息”里一键添加。

## 行为细节

- 会话隔离：群聊里新 @ 机器人的消息开启新话题、新建智能体；在同一话题内继续回复（root/thread 相同）则复用该话题的智能体，上下文连续。单聊以 `chat_id` 为一个持续会话，不再每条消息新建。同一话题内串行处理（上一轮未结束时新消息排队，排队状态在设置界面可见），不同话题并行；每话题最多排队 20 条，超出会回复提示。
- 轮次完成以 `turn_ended` 为唯一权威信号；重复/迟到的完成事件会被忽略。`run()` 返回 idle 后 5 秒内仍未收到 `turn_ended` 时，才用 `run()` 的最后消息合成一次完成，避免队列永久卡住。
- 一轮卡死超过 30 分钟时，下一条消息会触发重建；旧轮次的 pending 目标会被清空并通知原话题，旧轮次的完成结果不会再写入新会话。
- 处理中发起权限请求且开启 `notifyPermission` 时，通知会发到**该智能体所属话题**（不是群里最新消息），请在 Paseo 客户端里批准 / 拒绝，处理完成后结果自动回到原话题。
- 对 `dsh` provider，插件创建会话时会固定使用**最深思考**（`thinkingOptionId: max`）和 `paseo_dsh_permission_preset: danger-full-access`，避免群聊轮次停在权限确认上；其他 provider 不强制这些设置。
- 回复内容为该轮最后一条助手消息；中英文混排时只剔除**开头**的英文推理段，保留换行、列表和 fenced code，不再把中文答案截成最后两句。当轮次结束事件未携带文本时（部分 provider 的时间线投影、权限批准后继续的轮次会出现），先取 `run()` 返回的最后消息，再主动拉取智能体时间线兜底。
- 事件子进程异常退出或启动失败（如 ENOENT）后按指数退避自动重启（1s → 60s 封顶）；发送失败只写插件日志（`paseo plugin logs lark-bot`）。回复内容通过 stdin 传给 lark-cli，不出现在本机进程参数里。
- daemon 重启后、插件还没拿到 PaseoApi 前，事件会先进入有界缓冲（最多 50 条），拿到 API 后回放；超过上限的旧事件会被丢弃。
- 话题内的回复会携带上下文：**首次** @ 时带话题根消息和之前已记录的消息；同一话题的**后续** @ 不再重复根消息，只拼接“上次触发之后到本次 @ 之前”的新消息（智能体本身已保留前几轮上下文）。历史只对已绑定会话记录，每话题最多 50 条；单聊同样只拼接上次触发之后的新消息，首次最多带最近 20 条。历史在内存中积累，守护进程重启后只能靠根消息兜底。
- 话题历史中不同发送者用稳定标签区分（能从话题根消息拿到真名时用真名，否则按出场顺序记为 成员A/成员B/…，机器人固定为「机器人」）；图片、视频、文件、语音等非文本消息以 `[图片]`、`[视频]` 等占位记入历史。
- **图片与视频会传给智能体**：话题内出现的图片（包括 post 内嵌图片）自动下载缓存；视频用 ffmpeg 在整段视频上均匀抽 3 帧（有 ffprobe 时按 15%/50%/85%  seek，缩至 640px 宽），下次 @ 机器人时随消息附加（每次最多 4 张、每话题缓存 8 张，超过丢最老），prompt 末尾附「【附图】」说明。图片下载上限 5MB、视频 50MB；需要本机可访问 `/opt/homebrew/bin/ffmpeg` 或 `/usr/local/bin/ffmpeg`（无则视频退化为占位）。能否真正识图取决于所选 provider 的视觉能力，请以实际 provider 为准。
- 创建的智能体会话标题为「飞书 · 会话名 · 任务摘要」，带 `lark-bot-chat` / `lark-bot-topic` 标签，可在 Paseo 客户端中查看完整时间线并手动接管。注意：在 Paseo 里手动给该 agent 发消息产生的轮次也可能被当作插件轮次回复到飞书；建议在独立话题/会话中使用。

## 开发与验证

```bash
npm install
npm test
npm run typecheck
```

改动后执行 `paseo plugin reload lark-bot`（会重启事件监听与所有进行中的轮次等待，不影响 Paseo 里已有的智能体会话）。

## 安全与隐私

- **App Secret 按当前本地使用场景明文保存在 Paseo host 设置中，不做加密**。能打开该设置界面的本机客户端可以读回该值；请确保本机账户、备份和屏幕共享安全。lark-cli 自己仍会把凭证写入系统钥匙串，插件保存的是面向本机配置的副本。
- 群成员、其他机器人以及能单聊机器人的人都可以驱动智能体。插件没有内置用户白名单；默认 `cwd` 是用户主目录。请给机器人绑定专用低权限目录，并在 Paseo 侧限制 provider 的工具权限；不要把高权限工作区直接暴露给不信任的群。
- **dsh 会话由插件强制开启完全权限并自动接受权限请求**。这会让群成员通过机器人直接执行本机工具，仅应在可信群、可信工作区使用；不要把 `cwd` 指向敏感目录。
- 已绑定会话的文本、图片、视频和话题历史会发送给所选 provider（第三方模型）。未绑定会话不会被采集；如需接收未 @ 的群消息，必须额外开启敏感权限 `im:message.group_msg`，请先确认群成员的知情与同意。
- 插件有每话题队列上限，但没有按用户/时间的全局限流；群内刷屏仍可能产生较多模型调用，建议只在可信群使用。

## 已知限制

- 只处理 text / post 的指令；文件、语音、表情、卡片等非文本类型只记占位，不会把二进制传给智能体。post 的入站文本由 lark-cli 预渲染，排版细节以实际渲染为准。
- 群聊上下文/媒体/群列表依赖上文列出的额外权限；只授予 @ 权限时，插件仍能回复简单文本，但话题根消息、历史和图片会静默降级（日志可见）。
- 视频抽帧依赖 ffmpeg/ffprobe；没有时退化为占位。图片/视频大小超过上限会跳过。
- 机器人自己发起的回复不会触发其他会话轮次，但若 post 回复中 @ 了其他机器人，对方 agent 的响应由对方的接入方处理；双向接力可能形成循环。
- 与 lark-notify 同时启用时，本插件创建的会话轮次结束也会触发 lark-notify 的私聊通知（可在 lark-notify 设置里关闭）。
- 仅支持飞书中国区（`open.feishu.cn`、`--brand feishu`），不计划支持国际版 Lark。
- daemon 重启后的缓冲上限为 50 条；超过上限或缓冲期间插件始终未拿到 PaseoApi 时，旧消息会丢失。
